# 实现现状

## 当前状态

- 根 `PLAN.md` 是第一版产品范围、输出规范和验收标准。
- 当前不提供跨版本通用包；4.0.2、4.1.1、4.2.0、4.5 LTS、5.2 LTS 各自构建、声明版本上下界并独立验收。
- M1 已完成：纯 Python 的领域规则、任务状态模型、固定输出目录与原子 JSON 已落地。
- M2 已完成：Extension 注册、Output Properties 面板、Modal/handler 调度骨架、Beauty 批量渲染、增量清单和状态事务已落地。
- Blender 5.2.1 后台双摄影机真实渲染通过；Blender MCP 已确认 GUI 会话中的面板和 Operator 注册。
- M3 已实现不透明/透明两条 Alpha 路径，以及基于 evaluated depsgraph 的隔离 Object ID Scene、实例稳定键和颜色清单。
- 集成测试逐像素验证 ID PNG 只包含黑色与声明颜色，且 Alpha 同时具有透明/不透明值；MCP GUI 三通道批次完成且无临时 Scene 残留。
- M4 已完成取消、单项失败继续、批次级失败、load/unregister 清理、正式 RenderInfo 命名和完整运行元数据。
- Blender 4.5.11 与 5.2.1 LTS 全量后台测试通过；两版本的 Extension ZIP 验证、安装、启用与卸载通过。
- 已加入持久化双摄影机演示场景，并在 Blender 5.2.1 的真实安装态完成三通道渲染、MCP 注册检查和输出图像目视验收。
- 辅助渲染兼容 Blender 4.0.2–5.2 的 EEVEE 引擎标识；Alpha 写出会显式修正 Blender 像素扫描行方向，并以单通道连续数组交给 OpenImageIO。
- 控件同时注册在 Output Properties 和 `3D Viewport → N → Batch Render`，两处复用同一绘制函数与运行状态。
- 0.1.1 已修复 Cancel Batch 的上下文异常：取消只设置协作式停止请求，当前图片完成后终止队列，并在 GUI 活跃渲染中完成实测。
- 0.2.0 将 Python 基线降至 3.10，通过 `domain.compat.StrEnum` 与 `datetime.timezone.utc` 兼容 Blender 4.0/4.1 内置 Python。
- Blender 4.0.2、4.1.1、4.2.0 与 5.2.1 的后台全通道/取消/故障/恢复测试通过；4.0.2/4.1.1 Legacy 安装态和 4.2.0 Extension 安装态通过。
- 构建脚本从同一源码生成 `camera_batch_renderer-0.2.0.zip`（4.2+）与 `camera_batch_renderer-0.2.0-legacy.zip`（4.0.2–4.1），没有分叉业务实现。
- 0.2.1 将 Legacy ZIP 改为确定性构建，相同源码重复构建具有相同 SHA-256；Extension 与 Legacy 均检查清单、入口、缓存和意外文件。回归审查结果见 `Docs/过程产物/review/COMPLETED-v0.2.1回归审查.md`。
- 0.2.2 修复 GUI 异步批量渲染在完成事件遗漏或上一渲染任务尚未完全退出时停止推进的问题；每次启动异步渲染时只在调用栈内临时抑制新渲染窗口，并通过 `finally` 立即恢复用户偏好；调度器同时等待 Blender 渲染任务空闲，并以当前动作的已写出目标文件作为完成信号的安全后备。停止按钮只提交协作式请求，不伪造 Blender 渲染取消事件，确保已写完的当前图片先记账再停止。
- 0.3.0 删除批次 ID、批次前缀和 `001/002` 目录；输出固定写到 `.blend` 旁的 `SekerRenderAllCameras/`。新图先写临时目录，成功后原子覆盖同名旧图；本次未生成的旧图保留。RenderInfo schema 升为 2 并移除 `batch` 字段。
- 0.4.0 新增 Camera + Light Collection + World 可选配对。灯组包含子 Collection，配对 Camera 渲染时忽略其他 Light；未配对 Camera 沿用 Scene 默认。World 和 Light 可见性纳入统一状态事务，RenderInfo schema 2 以可选 `environment` 字段记录实际配对。
- 0.4.0 已在 Blender 5.2.1 通过后台 Beauty/Alpha/Object ID、GUI 连续渲染/取消、成功/失败/取消状态恢复、Extension 校验/双包构建和 Legacy 隔离安装验证。
- 0.4.1 修复隐藏/排除灯组被拒绝和配对列表不自动预览的问题。渲染事务新增 Collection `hide_render` 与 LayerCollection `exclude` 快照；预览经 `blender.environment.preview_environment` 单一边界同步 Camera、World、Light 对象和 Collection 可见性。
- 0.4.1 已在 Blender 5.2.1 用独立 EEVEE 场景完成环境配对验收：两套初始隐藏并从 View Layer 排除的灯组、两台 Camera 和两个 World 实际导出两张不同色彩的 PNG；同时核对 RenderInfo 配对记录及渲染后 Camera、World、Collection、LayerCollection 和 Light 状态恢复。产物保留在 `build/environment-pair-acceptance/`。
- 0.5.0 新增 Material ID：按 Blender Material 稳定分配非黑色 RGB，同一 Mesh 的不同材质面保持不同标签，未分配材质使用 `Unassigned` 标签；输出 `{Blend}_MaterialID.json`。实现只创建隔离的临时 Workbench Scene/Material/Mesh/Object，不修改用户材质。
- 0.5.0 已在 Blender 5.2.1 完成双材质面、未分配材质、黑色背景、PNG/JSON 逐像素一致、GUI 三摄影机六动作连续渲染、取消/失败清理和材质状态不变验收。可检查产物保留在 `build/material-id-acceptance/`。
- 0.5.1 在 Output Properties 与 3D View 共享面板底部显示运行版本；版本由 `camera_batch_renderer.version` 统一提供。
- `scripts/release_gate.py` 检查 Extension/Legacy 功能文件逐字节一致、两种 ZIP 文件名、manifest/项目/README/changelog 版本和首页下载 URL；`--verify-online` 在 GitHub Release 上传后验证两个最新版资产可下载。
- Blender 4.0.x 没有 `ID.is_editable`；灯光隔离预检通过 Blender 兼容层回退到 `library` / `override_library`，本地对象和库覆盖可编辑，直接链接对象仍会给出创建 library override 的错误。该路径已在 Blender 4.0.2 完成环境配对、全通道渲染、取消、失败和状态恢复集成测试，并用隔离用户目录验证 Legacy ZIP 安装生命周期。
- 当前源码已修复 Render Border + Crop 下 ID 通道尺寸不一致，并通过 Blender 5.2.1 验证 Beauty/Alpha/Object ID/Material ID 均为裁切后尺寸；同时使用 Blender 5.x `render.use_compositing` 正确关闭 Alpha 辅助场景的 Compositor。
- `scripts/run_full_test_suite.ps1` 是全量测试统一入口，逐步日志和 JSON 摘要写入 `build/test-reports/`；完整范围与未覆盖项见 `Docs/workflow/测试范围与发布验收矩阵.md`。
- `packaging/blender_targets.json` 是五个 Blender 发布目标的唯一真相源；构建阶段为每个 staging 包写入固定 `host_policy`，包内不按运行时版本自动选择策略。
- GUI 批次改为应用 timer 分段驱动，每次只同步执行当前动作，避开 4.0/4.2 的退出崩溃和 4.5 首图后异步调度停滞；取消仍在当前图片记账后停止。
- 2026-09-16 发布模式报告 `build/test-reports/20260916-115029-21724/summary.json` 在 Blender 4.0.2、4.1.1、4.2.0、4.5.13、5.2.1 上 50 项通过、0 项失败。
