## 当前未发布修复（2026-10-15）

- GUI 使用固定 `AsyncTimerDriver`：打开一次原生 Render Result 窗口，后续复用；Cycles/EEVEE 异步渲染，Workbench（含 ID 通道）保留同步调用以规避旧 Windows GL 驱动崩溃。显示偏好在调用栈内恢复，后台同步入口不变。
- 完成/取消 handler 仅接收当前动作的 Scene。队列等待 `RENDER` job 空闲后才提交图片、删除辅助 Scene 或开始下一项；长渲染不按耗时中止。无 handler 且无新 staging 文件的空闲状态持续两秒时记为失败，避免无提示永久等待。
- 预览与渲染共用集合切换边界：只切换已登记 Light Collection 根，保留对象 hide_render/hide_viewport/eye，保留子集合、未配对集合和父集合的手动状态。未配对灯光沿用场景状态；希望参与预设切换的灯组需登记到配对列表。集合内非灯光对象随集合显隐。
- 不再通过 exclude=True 隐藏非活动预设，避免 Blender 重建 View Layer 对象时丢失手动 eye 状态。显式启用一个被排除的预设根时，保存并恢复 Blender 自动连带改变的子层排除状态；不展开手动隐藏的父级。
- 临时事务仅恢复本批管理的集合根，并覆盖所有 View Layer；不向用户 Light 对象写入显隐属性。预览是用户显式切换结果，批次完成后回到批次前的预览状态。
- Windows 临时工作目录清理遇到短暂 sharing lock 时最多等待 0.35 秒重试；持续锁定明确报错，不再忽略删除失败后要求用户重复点击。启动异常经 session.abort_start 恢复事务、标记失败，并在面板保留错误；运行中按钮给出禁用原因。
- Alpha 与 ID 像素读取使用 foreach_get 写入 float32 缓冲，ID 按 65536 像素分块转换，避免整图 Python float list/tuple。4.0.2/5.2.1 已验证 4K 调色板与全部 Alpha 字节一致。
- 渲染 job 活跃期间禁用插件，既有 driver 请求当前图片后停止并延迟注销；只有 job 释放辅助 Scene、完成输出记账及事务恢复后才移除类、属性和 timer。
- 重点套件 `build/test-reports/20261015-141154-28128/summary.json` 为 39 passed / 1 failed / 0 not_run：5.2.1 Cycles GUI 通过，4.0.2 首图保存后在 GLFrameBuffer::bind 重绘路径崩溃；该失败不同于已在两个版本无插件原生对照中复现的 Intel GL DLL 退出崩溃。不得把历史通过写成本轮通过。
- 验证报告与最终兼容结论见 [实施计划](../过程产物/Plan/BLOCKED-渲染可观察性与集合显隐.md)。本机 Cycles 仅检测到 CPU，GPU 故障原因尚不能确认。

## 已落地映射

### 2026-10-15 Cycles 与首次启动续查

- 原问题第 4/7 项补充独立诊断机制：GUI operator 在预检前创建 `DiagnosticJournal`，Session 持有可选 journal，既有 driver 转发事件。文件使用 `AtomicJsonWriter` 原子替换与 fsync；每请求一个唯一 JSON，保留最近 128 事件、32 错误，异步渲染期间约每 5 秒记录一次，不新增渲染时限。
- 主目录为 `.blend` 同级 `SekerRenderAllCameras/Diagnostics/`，备用目录为系统临时目录下 `RenderAllCameras-Diagnostics/`。面板 **Open Diagnostics** 可打开本次路径，重启后从已存在的主目录/备用目录定位；运行时路径属性不保存到 `.blend`。日志写入失败显示错误且不阻断渲染。
- 内容包括宿主/插件/Python/系统版本、显示 GPU/驱动、Cycles 设置和已有设备缓存、通道、动作、输出路径、原生 job/事件、耗时与 Python traceback。没有设备刷新、环境变量采集、自动上传或场景数据导出。原生崩溃只能保留最后检查点，不保证获得崩溃原因或持续心跳。
- 两个重点版本初始上下文矩阵 12/12 通过（36 批、288 图）；加入诊断后的当前源码四通道矩阵 4/4 通过（12 批、96 图），见 `build/cycles-start-baseline/summary.json` 与 `build/cycles-diagnostics-transitions/summary.json`。一次有效请求即启动，运行中重复启动被拒绝。
- 诊断专项 12/12 功能断言通过，11/12 进程正常退出；4.0.2 启动故障注入完成后退出码 11，原始记录保留在 `build/render-diagnostics-priority/summary.json`。第 6 项退出问题按用户要求排除，不继续调查。正式配置哈希不变。

### 2026-10-15 逻辑审查增量

- Camera 名清理后在统一的 64 字符预算内分配唯一后缀；长组件和长路径截断保留确定性摘要。最终输出路径在创建工作目录前检查大小写不敏感碰撞，环境配对校验也提前完成。
- 透明 Film 下仅当本批 Beauty 为保留 RGBA 的 PNG/TIFF/单层 EXR，且不经实际 Compositor/Sequencer 输出时复用 Alpha；其他情况使用关闭 Compositor 和 Sequencer 的隔离 Alpha Scene。
- 图片已经提交后的清单或辅助清理失败通过 `BatchIntegrityError` 终止整个批次，不将错误记录到下一台 Camera。结束时独立尝试辅助清理和宿主恢复，清理失败不再静默算成功。同步入口的单项渲染失败可继续下一项。
- 完成/取消/load_pre handlers 使用 persistent，打开新文件后仍有效。两张图片之间的停止请求在启动下一张之前生效；运行中输出选项禁用。
- 辅助 Scene 构造异常会回收已创建的数据块；ID 显式使用源 Scene 的首个 View Layer 获取 depsgraph，并复制求值后的 Camera，不依赖渲染窗口当前显示的 Scene。空 Object ID 输出写出空映射，替换旧批次映射。
- 状态事务恢复子帧值；尺寸元数据按 Blender 的整数缩放及分别截断边界坐标计算，避免非整数分辨率/裁切导致的文件名与实际像素不一致。
