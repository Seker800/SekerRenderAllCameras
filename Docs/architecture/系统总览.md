# 系统总览

## 用户链路

用户在已保存的 `.blend` 中配置当前 Scene，可选为 Camera 配对 Light Collection 和 World，确认附加通道后启动任务。系统冻结任务输入、稳定收集 Camera，按 Camera 临时隔离灯光并切换 World，将新图写入 `.blend` 旁固定的 `SekerRenderAllCameras/` 目录，并在成功、取消或异常后恢复所有临时 Blender 状态。

## 逻辑分层

```text
Blender UI / Operators
        |
        v
Application（用例、任务状态机、协调）
        |
        +----> Domain（命名、计划、结果、稳定颜色等纯规则）
        |
        v
Blender Adapters（bpy、Render Result、Workbench、handlers、timer）
        |
        v
Infrastructure（文件系统、JSON、日志、时钟）
```

- `Domain`：纯 Python 规则，不导入 `bpy`，可在普通 Python 中确定性测试。
- `Application`：拥有批量任务生命周期，只依赖契约；不直接散落操作 `bpy.context`。
- `Blender Adapters`：把 Scene、Camera、渲染、图片和 UI 生命周期转换为项目契约。
- `Infrastructure`：原子写文件、清单序列化、路径和日志，不拥有渲染规则。
- `Presentation`：Properties、Panel 与 Operators，只收集意图和展示只读状态。

## 核心模块

- `BatchJob`：唯一任务状态、取消语义、逐摄影机调度与最终摘要。
- `RenderPlan`：冻结的场景、帧、摄影机顺序、每机灯光/World 环境、通道与输出格式。
- `Naming`：固定输出目录名、合法文件名和自然排序。
- `Beauty`、`Alpha`、`ObjectId`、`MaterialId`：各输出通道的执行与结果，不自行推进整个任务。
- `StateSnapshot`：捕获并恢复所有临时 Blender 状态。
- `Manifest`：RenderInfo、ObjectID 和 MaterialID 清单的版本化写入。
