# 系统总览

## 用户链路

用户在已保存的 `.blend` 中配置当前 Scene，可选为 Camera 配对 Light Collection 和 World，并从 Beauty、Alpha、Object ID、Material ID 中选择至少一个输出后启动任务。系统冻结任务输入、稳定收集 Camera，按 Camera 临时隔离灯光并切换 World，将新图写入 `.blend` 旁固定的 `SekerRenderAllCameras/` 目录，并在成功、取消或异常后恢复所有临时 Blender 状态。Beauty 默认开启但不是隐式必选项；只选任一辅助通道时不会暗中执行 Beauty。

## 逻辑分层

```text
Blender UI / Operators
        |
        v
Application（用例、任务状态机、协调）
        |
        +----> Domain（命名、计划、结果、稳定颜色等纯规则）
        |
        v
Blender Adapters（bpy、Render Result、Workbench、handlers、timer）
        |
        v
Infrastructure（文件系统、JSON、日志、时钟）
```

- `Domain`：纯 Python 规则，不导入 `bpy`，可在普通 Python 中确定性测试。
- `Application`：拥有批量任务生命周期，只依赖契约；不直接散落操作 `bpy.context`。
- `Blender Adapters`：把 Scene、Camera、渲染、图片和 UI 生命周期转换为项目契约。
- `Infrastructure`：原子写文件、清单序列化、路径和日志，不拥有渲染规则。
- `Presentation`：Properties、Panel 与 Operators，只收集意图和展示只读状态。

## Blender 版本边界

- Domain、Application 和 Infrastructure 只保留一份，不判断 Blender 版本。
- 每个受支持 Blender 目标在构建时写入固定 `host_policy`、版本上下界和包型；发布包运行时不根据 `bpy.app.version` 猜测适配路径。
- 4.0.2、4.1.1 使用各自的 Legacy ZIP；4.2.0、4.5 LTS、5.2 LTS 使用各自的 Extension ZIP。一个版本通过不能替代另一个版本的验收。
- GUI handler/timer、同步/异步渲染调度和未来宿主 API 差异由 Presentation/Blender Adapter 的目标策略拥有，不得渗入纯核心。

## 核心模块

- `BatchJob`：唯一任务状态、取消语义、逐摄影机调度与最终摘要。
- `RenderPlan`：冻结的场景、帧、摄影机顺序、每机灯光/World 环境、通道与输出格式。
- `Naming`：固定输出目录名、合法文件名和自然排序。
- `Beauty`、`Alpha`、`ObjectId`、`MaterialId`：各输出通道的执行与结果，不自行推进整个任务。
- `StateSnapshot`：捕获并恢复所有临时 Blender 状态。
- `Manifest`：RenderInfo、ObjectID 和 MaterialID 清单的版本化写入。
- `OutputAllocation`：唯一分配最终输出目录与隐藏工作目录；运行期 staging、marker 和 JSON 临时文件不得散落到输出根目录。
