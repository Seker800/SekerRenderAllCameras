# 架构约束

## 所有权

- `BatchJob` 是任务状态、进度、取消、错误汇总与完成判定的唯一写入者。
- `RenderPlan` 是一次任务冻结输入的唯一真相源；任务开始后不再从 UI 属性动态读取配置。
- `Naming` 是固定输出目录名、文件名清理和自然排序的唯一规则源。
- `StateSnapshot` 是临时 Blender 状态恢复的唯一责任点；通道实现不得各自保存不完整的零散副本。
- `Manifest` 只记录其他模块给出的事实，不重新推导渲染结果或对象颜色。

## Blender 隔离

- `Domain` 不导入 `bpy`，不接收 `Scene`、`Object`、`Image` 等宿主对象。
- `bpy.context` 只能在 Presentation、组合根和 Blender Adapter 边界读取；核心用例接收显式依赖和冻结数据。
- Operator 只做参数校验、启动/取消和用户反馈，不承载渲染循环、命名算法或状态恢复。
- `register()` / `unregister()` 必须对称、幂等；handlers、timers、属性与类必须全部可撤销。

## 事务与恢复

- 开始前完成预检和输出计划，再创建任务状态；可提前发现的错误不得在渲染到一半后才暴露。
- 所有临时状态修改都发生在统一事务中，并由 `try/finally` 保证恢复。
- 单台摄影机或单个附加通道失败可以记录后继续；无法保证状态恢复、清单一致或输出安全时必须终止任务。
- JSON 和图片都先写输出目录内的临时路径，成功后再原子替换同名正式文件；失败或未执行不得损坏旧输出。
- 插件不得自动保存 `.blend`。强制关闭 Blender 时依靠“不保存临时状态”避免污染磁盘文件。

## 可重复与可观察

- 摄影机排序、Object ID/Material ID 颜色和文件命名在相同输入下必须确定。
- 每个输出记录摄影机、通道、目标路径、状态、耗时和错误摘要。
- 日志不得包含用户密钥；绝对路径仅写入用户明确要求的本地 RenderInfo。
- 性能优化不得绕过恢复、覆盖/保留契约或可验证性。
