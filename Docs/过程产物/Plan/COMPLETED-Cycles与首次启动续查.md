## 用户授权的诊断文件机制

- 用户无法提供通道和 GPU 信息，明确允许无法定位时建立报错文件机制。新增范围：Infrastructure 的独立 DiagnosticJournal 原子 JSON、Blender 宿主信息采集、既有 Session/Driver 事件、面板打开文件夹入口。
- 唯一所有者：Session 持有可选 journal，driver 只转发事件；journal 不控制任务，不成为第二状态机；设备信息只读取当前缓存与 GPU 平台，不刷新设备、不加载驱动、不调用外部程序。
- 选择每次请求一个独立 JSON，放在输出目录 Diagnostics/，持续原子替换且 fsync；失败/崩溃后不被下次工作目录清理覆盖。拒绝只在异常时才写，因为 native crash 无 Python 异常。每五秒更新存活信息但不添加渲染时限，事件尾部有界。
- 记录范围：版本、操作系统、Python、当前渲染设备/设置/通道、当前动作、输出路径、原生 job/事件、耗时和 traceback；不收集场景几何、材质内容、账号、环境变量或其他用户文件。崩溃时最后记录仅代表最后检查点，不能伪造 native crash 栈。
- GUI 在 create_session 前创建日志，捕获预检/启动失败；主目录不可写时尝试系统临时目录（不使用退出后删除的 Blender 实例临时目录），全部失败明确提示。日志失败不能阻止渲染或恢复。
- M4：纯 Python 验证原子写失败、尾部边界/节流、失败保留；两个重点版本验证正常、启动拒绝、单项故障、取消、故意终止独立测试进程后日志仍可读及正式配置不变。
