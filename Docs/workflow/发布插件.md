# 发布插件

- 确认版本号、目标 Blender 版本与 changelog 已更新。
- 运行全量测试并保存可复查摘要。
- 从干净工作树构建 ZIP，只包含可安装插件文件和许可证/用户说明，不包含测试缓存、RenderOutput、`.blend1`、个人配置或开发文档。
- 在五个目标 Blender 的干净用户配置中安装各自 ZIP，验证启用、运行、禁用和卸载。
- 用最小 `.blend` 完成 Beauty、Alpha、Object ID、Material ID、取消和异常恢复验收。
- 记录 ZIP 哈希、构建来源和已知限制；发布失败时不得复用不明来源的旧包。
- 构建后运行 `python scripts/release_gate.py`：五包除目标入口、manifest 与固定宿主策略外，功能文件集合和内容必须逐字节一致。
- README 顶部按钮和安装章节必须指向当前版本的五个资产，不得保留旧版 URL。
- push、tag、GitHub Release 和五资产上传完成后运行 `python scripts/release_gate.py --verify-online`，并重新读取线上 README/Release；五个线上文件 SHA-256 均与本地已测试包相同才算发布完成。
- 用户明确要求 `commit and push` 时，运行时代码变化按 [`Commit与Push说明.md`](Commit与Push说明.md) 的发布型 push 执行。
