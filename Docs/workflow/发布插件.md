# 发布插件

- 确认版本号、目标 Blender 版本与 changelog 已更新。
- 运行全量测试并保存可复查摘要。
- 从干净工作树构建 ZIP，只包含可安装插件文件和许可证/用户说明，不包含测试缓存、RenderOutput、`.blend1`、个人配置或开发文档。
- 在目标 Blender 的干净用户配置中安装 ZIP，验证启用、禁用、重启、升级和卸载。
- 用最小 `.blend` 完成 Beauty、Alpha、Object ID、Material ID、取消和异常恢复验收。
- 记录 ZIP 哈希、构建来源和已知限制；发布失败时不得复用不明来源的旧包。
- 构建后运行 `python scripts/release_gate.py`：Extension 与 Legacy 除 Extension 专属 manifest 外，功能文件集合和内容必须逐字节一致。
- README 顶部按钮和安装章节必须指向当前版本的两个资产，不得保留旧版 URL。
- push、tag、GitHub Release 和双资产上传完成后运行 `python scripts/release_gate.py --verify-online`，并重新读取线上 README/Release；两个链接都可下载后才算发布完成。
- 用户明确要求 `commit and push` 时，运行时代码变化按 [`Commit与Push说明.md`](Commit与Push说明.md) 的发布型 push 执行。
