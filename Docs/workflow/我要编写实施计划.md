# 我要编写实施计划

计划存放在 `Docs/过程产物/Plan/`，文件名使用 `ACTIVE-主题.md`、`BLOCKED-主题.md` 或 `COMPLETED-主题.md`。根 `PLAN.md` 是当前产品需求基线，不代替实施计划中的架构、进度和验证记录。

以下情况实施前必须写计划：新功能、重要重构、跨模块改动、Blender 版本迁移、清单 schema 变更、状态恢复边界变化，或需要多阶段验证的工作。

每份计划必须包含：

- 状态、日期、目标版本、入口、权威来源、前置依赖与阻塞。
- 用户可观察结果、范围、非目标和不可变边界。
- 当前实现、责任所有者、唯一真相源、依赖方向和公开契约。
- 至少两种方案的比较，或说明为何只有一种方案不违反边界。
- 对 `bpy.context`、全局状态、重复配置、临时 Operator 和第二条适配路径的反打洞审查。
- 可独立验收的里程碑、精确路径、预期结果和停止条件。
- 纯 Python、Blender 后台、GUI、失败/取消、状态恢复、性能与兼容验证。
- 幂等、失败恢复、回滚、文档影响、进度、发现、决策和结果复盘。

计划进入实施前必须回答：完成后如何观察、谁拥有状态、复用了什么、哪些 Blender 状态会临时改变、如何证明全部恢复、失败后会留下哪些文件、目标版本如何验证，以及实现者能否不依赖聊天记忆继续工作。
