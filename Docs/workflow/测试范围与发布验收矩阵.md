# 测试范围与发布验收矩阵

## 覆盖模型

测试按“输入 × Camera × 渲染设置 × 输出通道 × 生命周期 × Blender 版本”组合，而不是只验证一次理想路径。`A` 表示已有自动化，`P` 表示部分自动化，`G` 表示仍需补齐；任何发布必测项为 `G` 时都不得宣称全量通过。

| 范围 | 代表工况 | 当前状态 | 发布要求 |
|---|---|---:|---:|
| 预检 | 未保存 `.blend`、零 Camera、不可写目录、不支持格式、Multi-view、第三方引擎辅助通道 | P | 必须 |
| Camera | 1/多台、自然排序、透视、正交、隐藏/排除、中文、非法字符清理冲突、链接 Camera | P | 必须 |
| 几何 | 普通 Mesh、修改器、Geometry Nodes、Collection Instance、链接对象、Volume 跳过 | P | 必须 |
| 通道选择 | Beauty/Alpha/Object/Material 单选、任意组合、全不选拒绝、动作数不含未选通道 | A | 必须 |
| Beauty | 可选且默认开启；Workbench、EEVEE、Cycles；PNG/JPEG/TIFF/OpenEXR；Compositor、File Output、Border/Crop | P | 必须 |
| Alpha | Film Transparent 开/关、透明边缘、半透明、Holdout、玻璃、原始 Render Layer 语义 | P | 必须 |
| Object ID | 黑背景、声明色集合、实例稳定键、跨 Camera/重复任务/重开文件稳定、Volume 跳过 | P | 必须 |
| Material ID | 多材质面、共享材质、无材质、稳定颜色、用户材质与面索引不变、Volume 跳过 | A | 必须 |
| 环境配对 | Camera + 子 Collection 灯组 + World、空配对、隐藏/排除灯组、重复/失效配对 | A | 必须 |
| 输出可靠性 | 固定目录、成功覆盖、旧文件保留、原子 JSON、单一隐藏工作目录、staging/marker 生命周期、路径预算 | A | 必须 |
| 故障注入 | Beauty/Alpha/Object/Material、几何复制、图像写入、JSON 写入、异常与取消 | P | 必须 |
| UI/运行时 | 两处 Panel、开始/停止、防重入、handler/timer、load/unregister、连续批次、弹窗偏好 | A | 必须 |
| 安装生命周期 | 构建、校验、安装、启用、重启、升级、禁用、卸载、安装态端到端 | P | 必须 |
| 兼容矩阵 | 4.0.2、4.1.1、4.2.0、4.5 LTS 最新补丁、5.2 LTS 最新补丁 | A | 必须 |
| 压力与资源 | 50+ Camera、大量实例、高分辨率、长路径、重复 10 批、取消风暴、内存回落 | P | 发布前至少烟测 |

## 已自动化的具体断言

- `tests/unit/`：状态机、取消语义、命名/冲突/路径预算、调色板、固定目录、隐藏工作路径、原子 JSON 临时目录、渲染事件和发布包一致性。
- `tests/architecture/`：`bpy` 隔离、Operator 上下文、Python/Blender 最低版本和版本单一真相源。
- `scripts/run_blender_tests.py`：两 Camera × Beauty/Alpha/Object ID/Material ID、四个单通道、全不选预检、Film Transparent 开/关的 Alpha-only、透明 Alpha 复用、像素颜色集合、旧输出保留、取消、故障、隐藏工作目录、环境配对和注册清理。
- `scripts/run_blender_edge_cases.py`：预检、透视/正交、隐藏 Camera、清理后重名、四种 Beauty 格式、Compositor/File Output、Render Border/Crop 四通道尺寸一致和 `.blend` 字节不变。
- `scripts/run_gui_render_tests.py`：目标宿主策略下的 GUI 连续调度、Beauty + Material ID 与 Material ID-only 连续批次、全不选报错、协作式停止、隐藏 incomplete 状态、无额外渲染窗口和偏好恢复；完成事件缺失后备由纯逻辑测试覆盖。
- `scripts/run_environment_pair_acceptance.py`：真实 EEVEE 红/蓝环境图像差异、配对记录和宿主状态恢复。
- `scripts/run_material_id_acceptance.py`：多材质面、未分配材质、黑背景、PNG/JSON 逐像素集合和用户材质不变。
- `scripts/run_installed_demo.py`：已安装 Extension 的公开身份、面板四开关/默认值、完整四通道、四个单通道、全不选拒绝与状态恢复。
- `scripts/test_legacy_install.py`：Legacy 安装、启用、Panel 注册、同一安装态功能契约、禁用和目录清理。
- `scripts/test_target_version_rejection.py`：在每个精确 Blender 版本中拒绝相邻目标包，防止拿错包静默启用。
- `scripts/run_stress_smoke.py`：每个版本真实渲染 50 Camera，并连续运行 10 个三 Camera 批次，检查输出集合、活动 Camera 和临时数据清理。
- `scripts/verify_cross_version_contracts.py`：对五个安装态演示的公开身份、UI 选项、单通道语义、结果数、文件后缀、清单结构和 Object/Material 调色板做跨版本一致性比较。

## 必须继续补齐的高风险缺口

以下项目不能依赖用户发现问题，下一次发布前应转为自动化 fixture 或明确阻断：

1. Cycles 全通道、Geometry Nodes、Collection Instance、链接库对象/Camera 的实际像素与稳定键测试。
2. Alpha 的半透明、Holdout、玻璃边缘以及 Blender 5.x Compositor API 下“Beauty 使用最终 Composite、Alpha 绕过 Composite”的对照图。
3. 图像 `os.replace` 失败、JSON `fsync/replace` 失败、磁盘满/只读目录和 Blender 渲染器抛错的端到端故障注入。
4. 插件运行中加载新文件、禁用插件、重复点击开始、防重入、重启后启用状态以及从上一版本升级。
5. 大量 evaluated instance、高分辨率、取消风暴和进程级内存回落测试；50 Camera 与连续十批烟测已经自动化。

## 版本与安装矩阵

| Blender | 包类型 | 最低验收 |
|---|---|---|
| 4.0.2 | `...-blender-4.0.2.zip`（Legacy） | 单元/架构、后台核心、边界、GUI、安装启用运行禁用卸载 |
| 4.1.1 | `...-blender-4.1.1.zip`（Legacy） | 同上 |
| 4.2.0 | `...-blender-4.2.0.zip`（Extension） | 官方 validate、全套源码态、GUI、隔离安装、安装态演示、卸载 |
| 4.5 LTS 最新补丁 | `...-blender-4.5-lts.zip`（Extension） | 同上 |
| 5.2 LTS 最新补丁 | `...-blender-5.2-lts.zip`（Extension） | 同上 |

每个 ZIP 只在配置声明的 Blender 版本区间使用，并在该目标精确补丁版本上测试。宿主策略、版本边界或共享代码变化后，五个产物必须全部重新构建并执行完整门禁。

## 发布结论模板

发布说明只允许包含以下可核验字段：候选 commit、版本、五个 ZIP SHA-256、每个 Blender 精确补丁版本、报告目录、通过/失败/not_run 数量、已知限制和阻断项。禁止使用“应该可用”“理论兼容”或把历史版本测试结果写成本次候选已通过。
