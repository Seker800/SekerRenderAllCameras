# 开发环境与插件

## 真相来源

- 目标 Blender 版本：确认后写入 `../reference/实现现状.md`，不得只记录在个人机器。
- Python 依赖与测试配置：实现时由仓库 `pyproject.toml` 锁定。
- 项目级 MCP 示例：根 `.mcp.json`；Codex 实际读取用户级配置，见 [`blender-mcp.md`](blender-mcp.md)。
- 产品范围与验收：根 `PLAN.md`。

## 必需软件

- Blender：优先选定一个 LTS 作为第一版唯一验收版本。
- Python：用于不依赖 Blender 的单元测试；版本应与目标 Blender 内置 Python 的语法兼容。
- Git；若提交 `.blend`、EXR 或大图，安装 Git LFS 并执行 `git lfs install`。
- `uv`/`uvx`：Blender MCP 上游推荐的运行方式。Windows 使用 uv 官方安装脚本，不使用 `pip install uv` 代替。

## 首次部署

- 执行 `blender --version`、`python --version`、`git --version`、`git lfs version` 和 `uvx --version`。
- 选择并记录目标 Blender LTS 版本。
- 按 [`blender-mcp.md`](blender-mcp.md) 安装 MCP addon、配置唯一客户端并从 Blender 侧启动服务。
- 初始化 Git 后执行 `git lfs install --local`，确认 `.gitattributes` 对测试 `.blend` 和大图生效。
- 在 Blender 的临时测试文件中验证 MCP 只读查询；不要用用户生产文件做首次连接测试。

## 最小验收

- Blender 可加载一个最小测试文件且 Console 无插件注册错误。
- MCP 能读取当前 Scene、对象和渲染设置。
- 普通 Python 单元测试不需要导入 `bpy`。
- Blender 后台测试可以使用目标版本启动，并把退出码返回给脚本。
- `git status --short` 不包含 RenderOutput、备份文件、缓存或个人凭据。
